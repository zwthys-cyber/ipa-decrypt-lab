## TestFlight 主人入口（2026-11-09）

主人在私聊中直接发送完整的 `https://testflight.apple.com/join/<邀请码>` 链接，即提交独立 TF 任务。后台检查资格、必要时有界接受邀请、获取可用测试构建并完成解密验证，再自动回传；不会改为下载 App Store 正式版。任务编号以 `tf_` 开头，`/status`、`/cancel`、`/get` 继续绑定原请求和主人。

TF 文件名带英文测试标识，例如 `CapyPlayer_Beta_1.1.7.ipa`，仅影响新发送的文件名称。应用包内容与版本不因此改变，旧消息中的文件不会自动改名。

其他白名单用户暂不开放 TF；TF 不支持 `/versions` 或指定 App Store 旧版本。会话或接口访问需要维护、额外协议、限流以及模型/明文验证失败时停止，不自动密码重登、申请新电脑授权或重发未知接受请求。接受过程中取消时保留未知意图，不继续发起读取或下载。详情与真实验证范围见 [TestFlight](TESTFLIGHT.md)。


@ipazake_bot 是管理员与白名单用户的私聊入口，服务器端在 Debian 13 VPS 常驻运行。当前支持按链接选择中国区或原外区账号的免费应用，IPA 最大 2000 MB，尚无收费入口。默认只有配置的管理员有权限，其他用户需要由管理员授权。

## 当前版本与登录修复

当前公开成品为 [v0.1.0-alpha.5](https://github.com/zwthys-cyber/ipa-decrypt-lab/releases/tag/v0.1.0-alpha.5)。Apple 新原生认证和 Store AMD/SP 注册已修复，正式运行包已通过 [X 下载与完整解密](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/42439908718/attempts/2)。此前因登录失败结束的任务可重新发送应用链接或 App ID；不会自动重放旧失败任务。本次实测没有重复 Telegram 文件发送，历史发送回执见文末。

日常任务仍使用 main 分支的精确源码指纹运行包，Release 是可下载的版本快照。缺包应先完成构建；新版发布不会自动重启常驻控制器。

## 首页与菜单

`/start` 打开简洁首页，只显示“下载旧版本”和“使用帮助”两个按钮，不显示今日次数。点击按钮在同一条消息内切换，二级页面提供“返回”。底部命令菜单只保留 `/start`、`/status`、`/cancel`；以下其他指令仍可手动输入。

## 指令

| 指令 | 行为 |
| --- | --- |
| /start 或 /help | 使用说明 |
| /latest AppID或商店链接 | 下载最新版；单独点击菜单会提示输入应用 |
| /decrypt | 保留为最新版入口的兼容别名 |
| /versions AppID或商店链接 | 查询历史版本并显示可点击、可翻页的按钮 |
| /version AppID或商店链接 版本号 | 实时请求指定旧版，例如 `/version 444934666 9.3.55`；也接受 Apple 历史版本 ID |
| App Store 链接或数字 ID | 默认创建最新版任务 |
| /id | 显示自己的数字 ID；未授权用户也只能查看自己的 ID |
| /status | 查看当前任务 |
| /cancel | 请求取消当前任务 |
| /get 任务编号 | 显式取回属于自己且尚未过期的文件 |
| /allow 用户ID [每日额度] | 仅管理员：授权或修改额度，默认每日 3 次 |
| /deny 用户ID | 仅管理员：移除授权并停止自动交付 |
| /users | 仅管理员：查看白名单与每人额度 |


直接发送链接或数字 ID 就是最新版，不需要额外加指令。菜单会在服务启动时注册。

## 国区历史版本用法（2026-11-10）

```text
/versions https://apps.apple.com/cn/app/id1661733229
/version https://apps.apple.com/cn/app/id1661733229 1.18.1
```

第一条查询并显示可点选的版本列表，第二条按版本号请求；也可用 Apple 历史版本 ID 替代版本号。国区与外区列表独立缓存，可翻页、刷新及加载更早版本。查不到目标、已不可下载、地区许可拒绝或版本不符时明确停止，不回退最新版或外区。用裸数字 App ID 仍会选择外区；TF 仍不支持这些历史命令。

## 链接地区自动识别

- `https://apps.apple.com/cn/app/名称/id1530340312`：中国区账号下载最新版。
- `/us/`、`/de/` 等其他地区链接：原外区账号。
- 数字 App ID 或没有地区的 Apple 链接：保留原外区默认。

同一应用可能在多个地区上架；机器人依据链接地区选账号，不从 App ID 猜测。外区仍沿用原美区预检，不是每个国家配置一个账号。进度卡显示下载地区；重启、取消和 `/get` 都保留地区绑定。国区下载失败不跨账号重试。

中国区支持最新版及可获取的历史版本。使用 `/versions 国区完整链接` 查询和点选，或 `/version 国区完整链接 版本号` 指定旧版；纯数字 ID 仍使用外区账号。版本查不到或校验不符会停止，不回退最新版或外区。国区登录状态需要验证时，提示管理员更新会话，下载用户无需提供 Apple 验证码。详见 [中国区账号](CHINA-ACCOUNT.md)。

目前抖音等国区专属应用存在地区许可兼容问题：实测国区登录成功，但 GitHub 美国出口下收到地区不可用相关响应，尚未修复。需要大陆出口做同版本对照，不能仅凭提示断言 IP 是唯一原因。遇到同样失败请保留任务编号，先核对 [国区当前限制](CHINA-ACCOUNT.md)，不要反复提交。

## 历史版本

提供两种入口：

- `/versions 444934666`：查询历史列表，每页 10 项，点击版本按钮提交下载。
- `/version 444934666 9.3.55`：指定显示版本号；也可以填写已知的 Apple externalVersionID。

两种入口都接受 App Store 链接，不接受 Bundle ID。至少 6 位、非零开头的纯数字按 Apple externalVersionID 处理，它与 Info.plist 的 CFBundleVersion 不是同一个字段。

首次查询最多核对最近 10 个历史标识，完成后立即显示按钮。需要更早版本时，点击“加载更早版本”，每次再核对最多 10 个标识。已经加载的页面可直接翻页，不启动 GitHub；单个应用最多展示 200 个版本。每批在请求之间检查 180 秒预算，连续 3 次元数据查询失败就停止；游标会跳过已尝试的标识，避免反复卡在同一版本。

最多缓存 50 个应用，24 小时内直接使用。超过 24 小时、未满 7 天的列表先显示旧缓存，空闲时后台刷新；忙碌时可以继续浏览，稍后点“刷新列表”。超过 7 天的缓存会删除。缓存和查询状态写入数据库，重启后保留。

首次查询和刷新至少间隔 60 秒，加载更早版本至少间隔 5 秒；这些远程查询合计每滚动 24 小时最多 20 次。点击“刷新列表”会重新查询最近一批。按钮仍在 6 小时后过期；重新发送 `/versions AppID` 可以从缓存打开新按钮。

指定显示版本号时，搜索上限为 120 个标识，同样有时间预算。Apple 不再提供下载、账号没有许可或版本匹配失败时，任务会停止，不退回最新版。旧版请求不拿最新版的商店大小作拒绝依据，实际文件仍受 2000 MB 限制。

按钮绑定请求用户、私聊、列表消息和有效期，使用状态先写入数据库，再提交任务。选择版本并通过任务检查后，列表自动收起为“已选择版本”的简短提示，所有版本和翻页按钮移除。收起状态在重启后保留，后台刷新也不会重新展开；需要再次选择时，重新发送 `/versions AppID`。

已实测 QQ 的按需历史目录：Apple 返回 335 个标识，[首批](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41952989754)和[下一批](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41953354529)各返回 10 项，标识不重叠。Apple 的 releaseDate 在这个样本里是应用首次发布日期，所以没有把它显示成每个版本的发布时间。

## 进度和文件

已部署的进度卡显示下载地区、流程进度条、已完成步骤数、当前阶段、总耗时、本阶段耗时、UTC 开始时间和任务编号。流程百分比按已完成步骤计算，明确标注“按步骤”，不代表已处理字节比例或预计剩余时间。只有 Telegram 确认文件发送成功后，整体才显示 100%。

下载阶段另外显示原生回调提供的真实字节百分比与已下载/总容量；没有可验证计数的阶段只显示阶段和耗时。Telegram 本地 Bot API 没有可靠的远端上传字节回调，因此上传时继续显示耗时，收到发送回执后完成。不会显示虚构的上传百分比或预计剩余时间。

计时约每 5 秒刷新，后台阶段和计数随上报更新。超过 30 秒没有新计数时，标明是最近观测值。总耗时从原任务创建开始，包含排队、准备、处理和交付；超过一天保留天数。卡片标识和时间写入私有恢复数据库，服务重启后继续累计，已完成任务的计时停止。也可以发送 `/status` 查询。

工作进度有 Actions 可读的短期数字快照作为读取路径；VPS 不需要额外申请 Checks 权限。缺少细节时显示“等待阶段更新”，不再把整个下载和解密过程误标成准备环境。alpha.3 起已打包进度和提速改动，alpha.4 进一步加入白名单；实际服务升级以部署记录为准。

交付文件使用 `名称_版本.ipa`，例如 `My BVF_5.2.3.ipa`。名称和版本取自校验后的 IPA，图标优先取包内 PNG，缺失时尝试 Apple 商店图标。商店图标可能对应最新版；取图失败不影响文件发送。文件附件不再附加校验说明和任务编号那三行文字。

如果出现“上次文件发送结果需要确认”，先查看聊天里是否已经收到文件。确认未收到后，再用 `/get 任务编号` 取回。保留这个判断，是因为 Telegram 发送和本地状态写入不能作为同一笔事务完成，超时不一定等于发送失败。

## 任务怎么处理

1. 服务器检查应用的美区上架状态、价格和标注容量。明确不支持时直接返回，不创建任务、不占提交额度。
2. GitHub macOS 获取匹配的预编译运行包，登录账号并请求下载。
3. 复用已有模型处理 IPA，核对所有加密切片、版本和摘要，清理 Store 账号元数据。
4. 用 age 加密结果，公开产物只保留一天。
5. VPS 解开交付密文，复核摘要和 IPA 结构，再通过本地 Bot API 发回任务所属用户的私聊。

没有把解密成功等同于安装成功；重签名和实际运行仍需另行验证。

同一时间只运行一个 Apple 下载或查询工作流；旧缓存后台刷新时可以提交下载，由 GitHub 串行执行。普通下载默认全服务每 UTC 日最多 20 次提交（包含失败任务），每人另有独立额度，白名单用户默认 3 次；提交间隔至少 30 秒。历史列表查询每人及全服务各受每滚动 24 小时 20 次限制，缓存浏览不占远程额度。其他用户有任务时，新查询/下载会提示稍后再试，不自动堆积任务。工作流默认使用 macOS 26 Intel，备用 macOS 15 Intel。只有确认原任务未执行且已终止，才允许安全切换，最多两次逻辑运行。

## 运行包和速度

已把逐任务编译改成约 28 MB 的成品包。代码更新时在 GitHub 构建和测试，普通任务直接下载并验证源码指纹、平台和摘要。

四个固定 Apple 公共资源单独缓存，每次仍校验长度和 SHA-256。缓存只包含公开资源，不包含账号会话、授权模型或 IPA。跨 macOS 运行器的实测中，恢复和校验合计约 6 秒；之前重新准备资源曾用 24–71 秒。

[My BVF 最新回归](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41953586939)约 59 秒，包准备 7 秒、公共资源恢复及校验 8 秒。历史查询进一步复用同批连接和公开端点后，[QQ 首批 10 项](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41956106639)约 55 秒，[下一批](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41956309828)约 1 分 3 秒。下一批与前次耗时接近，并非每次都会明显提速。这里记录的是工作流作业耗时，排队和 Telegram 展示、文件传输另计。

Actions 运行包保留 30 天，每周刷新。源码更新后需要先完成新构建；缺包时运行 `native-runtime-build.yml` 补齐，再提交任务。默认构建两个平台；手动可选择一个已支持平台进行完整恢复构建，但产物只能供该精确平台使用。

## 配置与恢复

将 Apple 账号和模型放在 GitHub Secrets。VPS 保存 Telegram 凭据、交付私钥、限定仓库权限的 GitHub token，以及 TF 会话的私有密文和接受意图记录；状态助手不解封 Apple 会话。部署配置见 [VPS 说明](VPS-DEPLOYMENT.md)，公开版本见 [发布说明](RELEASES.md)。

恢复记录保存在私有 SQLite。重启后继续跟踪原任务，不重复提交；发送结果不明时不自动重发。不要在另一台机器启动同一个机器人的轮询进程。具体规则见 [任务恢复](SESSION-RECOVERY.md)。

已取得过 [92 MB 文件的 Telegram 发送回执](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41864719056)，也在 [41940545752](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41940545752) 部署了带历史版本列表的服务。按需历史列表和扩展缓存已在 [41953590065](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41953590065) 部署。更多验证记录见 [项目状态](PROJECT-STATUS.md)。

新版卡片的[服务部署](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/42443436341)、[双平台运行包](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/42443706492)和[实际 X 导出计数](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/42444399936)均已验证。本轮实际导出没有额外发送 Telegram 文件；新建任务使用新版卡片，旧消息不会因发布说明更新而自动重写。

## X 导出加速（2026-11-08）

已上线保留压缩数据的账号清理流程，完整页面和 ZIP 校验不变。与截图对应的原任务比较，[新实测](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/42445425200) 的复核从 40.4 秒降到 13.8 秒，GitHub 后台从 2 分 08 秒降到 1 分 43 秒。包体约大 3%；用户全程还包含排队、服务器取回和 Telegram 上传，本轮没有重复文件发送，不将后台时长当作聊天里的总耗时。新任务自动使用匹配的新运行包。详见[项目状态](PROJECT-STATUS.md)。

## 白名单使用

先让对方在机器人私聊发送 `/start` 或 `/id`，把显示的数字 ID 发给管理员。管理员在自己的私聊发送 `/allow 用户ID 3` 授权，之后对方再使用机器人即可。`/users` 查看、`/deny 用户ID` 移除。管理员身份来自现有配置，不能通过这些命令转让。详见[多用户说明](MULTI-USER.md)。


## 中国区账号的独立接入状态（2026-11-09）

中国区模型恢复、跨运行器复用、保存状态重放和独立真实导出均通过。`/cn/` 链接使用国区账号，其余链接和数字 ID 使用原外区账号；国区支持免费最新版及可获取的历史版本。普通国区任务不挂载外区凭据、不预填验证码、不新增电脑授权；会话需要验证时由管理员维护。原德国区账号、模型和安全设置保持原样。详见 [中国区接入说明](CHINA-ACCOUNT.md)。
