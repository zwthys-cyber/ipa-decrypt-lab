# 中国区账号的独立接入

这是新增账号的分阶段接入，不更改现有德国区账号、默认下载线路、账号地区或双重认证设置。当前正常任务仍沿用原账号和原模型，不能把中国区登录成功等同于中国区下载解密已完成。

## 新账号凭据

在本仓库 Settings → Secrets and variables → Actions 中新增 `APPLE_CN_ID`、`APPLE_CN_PASSWORD`。不要覆盖原 `APPLE_ID`、`APPLE_PASSWORD`。账号和密码不应放在聊天、公开工作流输入、源码或日志中。

新账号已有双重认证且能接收验证码时，按正常可信设备或短信确认；验证码需要时临时配置 `APPLE_CN_2FA_CODE`，只接受六位数字，用后删除。`APPLE_CN_GUID` 是新账号独立且稳定的设备标识，保持与后续会话/模型接入一致，不替换原账号标识。

## 验证流程

`china-account-auth.yml` 默认为 `test`，只在 GitHub-hosted runner 跑合成隔离测试。显式 `authenticate` 才会取已验证的原生运行包、准备固定公共资源，再对新账号做一次登录；不加载原账号密码或模型、不下载 IPA、不做模型恢复/机器授权/撤销操作，也不更新现有任务服务。

登录凭据仅传给原生客户端；现有账号邮箱只用于确认新旧账号不同，不传给客户端。验证真实返回的中国区 storefront，错误地区不会被改标签或回退原账号。二次认证未完成、泛化 BadLogin 或网络失败不能算登录成功，不对未知认证问题盲目重试。

本阶段不保留登录会话或账号缓存，不上传账号文件、令牌、验证码或原始认证输出。后续需要另行验证受保护会话复用、地区预检/历史目录和独立中国区解密模型。不得在未证明兼容时把原账号模型直接交给新账号，也不得因新账号接入改变原账号的双重认证或授权设置。
