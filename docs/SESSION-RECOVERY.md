# 常驻服务任务恢复

将任务恢复逻辑放在 `tools/persistent_journal.py`，状态保存在 VPS 私有 SQLite 数据库，不再向 GitHub Checks 写入恢复记录。旧 Checks 实现和实验工作流已删除，历史证据可从 Git 历史与 [41890117885](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/41890117885) 查阅。

## 采用的恢复规则

- 提交前持久记录任务，失败即不提交；重启追踪已有任务，不重复下载。
- 更新处理意图先于副作用写入 SQLite，已认领的更新不会因崩溃自动重放。
- 发送前记录 sending；确认后记录 delivered。发送成功但记录失败时仍保留不确定状态，下次启动提示检查聊天，不自动重发。
- 已完成、取消或发送不确定的任务不自动交付；任务所属用户可明确使用 /get 取回自己的尚未过期文件。
- 取消意图先记录；API 失败不等于后台已停止，但不继续自动交付。
- 恢复任务不重复尝试结果不明的备用运行器提交。
- 最近一天存在多个未完成任务时停止自动恢复，要求人工按任务编号处理。

## 数据与边界

数据库使用 WAL、FULL 同步和私有文件权限，按请求用户隔离。机器人 token 轮换不改变本地记录命名空间。更新编号、任务编号和 App ID 留在私有数据库，不写入公开恢复日志。

同一服务通过文件锁防止双进程；这不是跨服务器分布式锁。Telegram 发送与 SQLite 写入不能构成原子事务，因此未知发送结果优先避免重复。数据库备份每小时和正常退出时生成，当前仅保存在同机。密文产物通常保留一天，数据库存在记录不保证产物尚未过期。

## 验证

`tests/test_persistent_service.py` 验证持久化、权限、更新去重、备份和运行边界；`tests/test_controller_recovery.py` 使用真实临时 SQLite 验证恢复控制器、写入失败阻断副作用、取消失败与发送不确定时不重发。仅在 GitHub 上运行这些测试。

部署与回滚见 [VPS 部署说明](VPS-DEPLOYMENT.md)。合成故障测试不代替真实 IPA 上传中断实测。

## 新版与旧失败任务

本规则在 v0.1.0-alpha.4 中继续适用。Apple 原生登录和设备注册已恢复，详细实测见[项目状态](PROJECT-STATUS.md)。升级运行包或发布 Release 不会清空私有 SQLite，也不会自动重放旧登录失败、已取消或发送结果不明的任务。管理员可以重新提交应用；只有确认发送结果且密文仍未过期时，才使用 `/get` 取回原任务。

新 Release 的发布不代表 VPS 已重启或控制器已部署；升级和回滚仍遵守[VPS 部署说明](VPS-DEPLOYMENT.md)。


## 进度卡恢复

main 的进度升级在任务所属用户作用域的 metadata 中保存卡片 message_id、阶段起点及完成状态；总时长使用 tasks.created，不因服务重启、重新读取工作流或切换未执行的排队线路归零。恢复沿用原卡片，不重新提交下载或发送文件。独立计时刷新只编辑已有卡片，不写 SQLite，也不触发文件发送；服务结束会停止刷新线程。

上述恢复与计时行为已进入本轮 449 项 Python 回归，并在 [42443436341](https://github.com/zwthys-cyber/ipa-decrypt-lab/actions/runs/42443436341) 部署。另有回归验证计时刷新后的限流不会丢弃新下载计数；下一次刷新采用最新值。这些合成故障检查不代表进行过真实上传中断测试；本轮实际 X 导出仅验证后端及数字快照，没有额外 Telegram 文件发送。

## 白名单与取消恢复

一个轮询进程共用管理员作用域中的全局更新游标；任务、列表缓存、进度和每日计数按每个用户原有 owner hash 隔离。管理员旧数据不迁移、不改写，整库备份包含所有用户的记录、私有白名单和取消确认占位。

撤权在同一 SQLite 事务中关闭权限、取消该用户待处理任务的自动恢复、关闭未完成版本查询，并记录需要确认终止的工作流。普通用户取消也持久记录意图及全局占位；重启后不自动发送已取消任务。发送结果不明的 sending 记录仍不自动重发。

只在确认原工作流已经结束后释放取消占位；找不到任务或接口结果不明时保留占位，等待平台或人工核对，避免盲目重提和覆盖队列。恢复和故障隔离由真实临时 SQLite 的合成测试覆盖，不等于进行了真实多用户上传中断测试。

## 链接地区与恢复

alpha.5 起中国区编号为 `cn_` 加 32 位摘要，旧外区编号仍为 32 位摘要。编号将账号选择绑定到 SQLite 记录、固定工作流、进度和交付收据；重启、取消、撤权和 `/get` 均沿用这一绑定，无需迁移既有表。国区任务不会参与外区备用运行器切换，也不会在失败后变成另一个账号的任务。两类任务共用既有用户配额和全服务串行准入。

## TF 请求的额外保护

TF 任务使用独立 `tf_` 编号，但仍保存在对应主人的私有任务账本中，恢复、取消和文件取回不跨用户。TF 不采用普通 App Store 的自动运行器切换，避免重新执行可能已经发生的加入操作。

接受之前，GitHub worker 经固定 SSH 向 VPS 提交与邀请码、任务、运行、源码绑定的意图；成功写入后才允许一次 POST。运行超时、取消或响应不明时意图不会自动到期重发，后续先读取资格。有资格就复用；没有资格且已有意图时停止，不能删除记录冒充未执行。明确的会话拒绝或限流也停止，不紧接着自动读取重试。

文件交付继续在上传前记录发送意图，确认后才完成；结果不明不自动重发。原来403,501字节的已确认回传受独立单次发送记录保护，本轮测试没有重复发送它。
